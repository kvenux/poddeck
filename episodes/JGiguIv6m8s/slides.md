# Agentic Social Network：社交单位的变化

<div class="text-sm opacity-70 mb-4">在微信、Facebook、WhatsApp、Twitter 里，社交的起点和终点都是<strong>"你"</strong>。但是——</div>

<div class="grid grid-cols-2 gap-6 mt-6">

<div class="p-5 rounded border-l-4 border-gray-400 bg-gray-50">

### 旧范式：人与人

<div class="text-sm opacity-80 mt-3">

- 社交的基本单位 = **人**
- 你发内容、你回复消息、你建立关系
- 所有行为的<strong>起点和终点都是我们自己</strong>

</div>

</div>

<div class="p-5 rounded border-l-4 border-blue-500 bg-blue-50">

### 新范式：人 + Agent

<div class="text-sm opacity-80 mt-3">

- 社交的基本单位 = **人 + Agent**
- 你的 Agent 帮你回复信息、参与讨论
- 7×24 小时存在；网络那头也可能是<strong>对方的 Agent</strong>

</div>

</div>

</div>

<div class="mt-6 p-4 text-sm border-l-4 border-orange-500 bg-orange-50 bg-opacity-30">

陈茜的比喻："就像两个领导要开会，<strong>下面的秘书和小助理先把流程、文件、议题进行对齐</strong>，到领导们真正要见面的时候，直接处理最重要的决策部分就好了。"

</div>

# 模型层：从"一个大脑"到"模型路由器"

<div class="grid grid-cols-2 gap-6 mt-4">

<div class="p-4 rounded border-l-4 border-gray-400 bg-gray-50">

### 旧逻辑：靠一个超强大脑

只要 GPT 类的"大脑"足够强，问题就能<strong>一次性解决</strong>。

<div class="text-xs opacity-70 mt-3">问题：成本极高、效果不稳定、所有任务都压在同一个模型上。</div>

</div>

<div class="p-4 rounded border-l-4 border-blue-500 bg-blue-50">

### 新逻辑：Model Router 调度

按任务挑模型——<strong>Claude 写代码强，有的模型适合图、有的适合视频</strong>。

<div class="text-xs opacity-70 mt-3">"我们会根据具体任务，灵活选择最合适的模型来调用。"</div>

</div>

</div>

<div class="mt-6 p-4 text-sm border-l-4 border-orange-500 bg-orange-50">

<strong>两个关键考量：</strong>

<div class="grid grid-cols-2 gap-3 mt-3">
<div>
<strong>1. 能力匹配</strong> —— 不同模型擅长不同任务，路由系统为每个任务找最匹配的模型。
</div>
<div>
<strong>2. 成本与效率</strong> —— 轻量模型不仅便宜，"<strong>甚至可以直接在本地运行</strong>"，可部署在手机上。
</div>
</div>

</div>

<div class="p-3 rounded bg-blue-50 border-2 border-blue-200">

准确度 vs 错判风险

</div>

<div class="p-3 rounded bg-orange-50 border-2 border-orange-200">

<div class="p-3 rounded bg-green-50 border-2 border-green-200">

### 速度
高并发 + 响应时间

<div class="p-3 rounded bg-red-50 border-2 border-red-200">

</div>

# 记忆层：Memory 才是 Agent 的"人格系统"

<div class="text-sm opacity-70 mb-4">在 Agent 体系中，"聪明"只是基础——真正关键的是它<strong>是否有记忆</strong>。</div>

<div class="grid grid-cols-2 gap-6 mt-4">

<div class="p-4 rounded border-l-4 border-gray-400 bg-gray-50">

### 没有记忆的 Agent

- 每次对话都从头开始
- 不知道你是谁、做过什么
- 不理解你真正的偏好与习惯

<div class="text-xs opacity-70 mt-3">"再强也只是一个更高级的工具。"</div>

</div>

<div class="p-4 rounded border-l-4 border-purple-500 bg-purple-50">

### 有 Memory OS 的 Agent

持续记录、整理、更新一整套关于"你"的状态：

- 偏好、行为轨迹、历史决策
- 不同场景中的上下文
- <strong>不断构建和修正一个关于用户的长期模型</strong>

</div>

</div>

<div class="mt-6 p-4 text-sm italic border-l-4 border-blue-500 bg-blue-50">

"简单来说，<strong>Memory 就像是 Agent 的'人格系统'</strong>。"

</div>

# 为什么大平台短期内不会"让 IM 给 Agent 用"

<div class="text-sm opacity-70 mb-4">何朝阳对"Slack/微信 + Claude Code"路径的判断：</div>

<div class="grid grid-cols-3 gap-4 mt-4 text-sm">

<div class="p-4 rounded bg-red-50 border-l-4 border-red-500">

### 隐私墙

"<strong>非常隐私化的 IM</strong>……怎么可能把隐私数据开给一个非常不安全的 Claude Code 呢？"

<div class="text-xs opacity-70 mt-2">"今天肯定是他们不愿意开接口。"</div>

</div>

<div class="p-4 rounded bg-orange-50 border-l-4 border-orange-500">

### 用户体验风险

"会不会影响原来人类的网络？<strong>万一破坏了用户体验怎么办</strong>？"

<div class="text-xs opacity-70 mt-2">"万一这个 Agent 去天天给人类打电话怎么办？"</div>

</div>

<div class="p-4 rounded bg-yellow-50 border-l-4 border-yellow-500">

### 记忆打不通

"Claude Code 那个 Memory 在你租房的那个房子里、<strong>那个边缘设备上</strong>——它跟你的 IM 里面人和人的记忆是没办法打通的。"

</div>

</div>

<div class="mt-6 p-4 text-sm italic border-l-4 border-blue-500 bg-blue-50">

何朝阳的判断：美国 IM 分得很细（Slack=工作 / WhatsApp=生活 / Telegram=兴趣 / Discord=社区），<strong>这一轮 "IM + Claude Code" 远远不够</strong>。

</div>

# 安全：激进派的"潘多拉魔盒"
